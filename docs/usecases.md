# 유스케이스

`README.md`의 기술, 보안, 계정, 메모, 태그, 필터를 사용자 동작으로 옮긴 문서다.

## 공통 전제

- 액터는 방문자와 로그인 사용자다. 메모, 태그, 필터는 로그인한 계정 안에서만 만들고 본다.
- 앱은 Vercel에 배포하는 Nuxt 3 + TypeScript 한 프로젝트다. 화면과 `server/api`를 같이 둔다.
- 화면은 PC와 모바일에서 모두 동작하는 반응형이다.
- 저장소는 Turso다. 접속 정보는 서버 환경 변수에만 둔다.
- 로그인 유지는 httpOnly 쿠키다. 브라우저 스크립트는 이 쿠키를 읽지 못한다.
- 비밀번호는 해시만 저장한다. 어떤 화면에도 기존 비밀번호를 다시 보여 주지 않는다.
- 메모 본문은 마크다운 문자열로 저장한다. 편집 화면은 위지윅이고, 저장되는 값은 그 화면이 만든 마크다운이다.
- 저장 상태는 저장 중, 저장됨, 실패, 충돌 중 하나다.
- 마지막 저장본은 서버에 마지막으로 반영된 본문이다. 현재 편집본은 위지윅에 있는, 아직 그 저장본과 같지 않을 수 있는 본문이다.
- 이메일 보안코드는 숫자 8자리 난수다. 코드를 요청한 흐름(로그인 또는 비밀번호 변경) 안에서만 쓰며, 별도 입력 페이지에서 제한 시간 안에 맞을 때만 인증된다. 제한 시간의 길이는 이 문서에서 정하지 않는다.

아래 유스케이스에 없는 동작은 범위 밖이다. 소셜 로그인, 메모 제목 필드, 메모 공유, 저장된 필터의 수정과 삭제가 여기에 해당한다.

## 계정

### UC-01 회원가입

- 액터: 방문자
- 사전 조건: 없음

기본 흐름

1. 방문자가 이메일과 비밀번호를 입력한다.
2. 시스템이 비밀번호를 해시로 저장하고 계정을 만든다.
3. 방문자는 그 이메일로 로그인할 수 있다.

예외 흐름

- 이메일이 비어 있거나 이메일 형식이 아니면 계정을 만들지 않고 입력 오류를 알린다.
- 비밀번호가 비어 있으면 계정을 만들지 않고 입력 오류를 알린다.
- 이미 가입된 이메일이면 계정을 만들지 않고 그 사실을 알린다.

사후 조건: 계정이 생기고 비밀번호는 해시로만 남는다. 이 흐름만으로 로그인 쿠키가 생기지는 않는다.

### UC-02 비밀번호로 로그인

- 액터: 방문자
- 사전 조건: UC-01로 만든 계정이 있다.

기본 흐름

1. 방문자가 이메일과 비밀번호를 입력한다.
2. 시스템이 저장된 해시와 입력한 비밀번호가 일치하는지 확인한다.
3. 일치하면 httpOnly 쿠키로 세션을 연다.
4. 로그인 사용자의 메모 목록으로 이동한다.

예외 흐름

- 이메일이 없거나 비밀번호가 다르면 세션을 만들지 않고 로그인 실패를 알린다.

사후 조건: 해당 계정의 세션 쿠키가 생긴다.

### UC-03 이메일 보안코드로 로그인

- 액터: 방문자
- 사전 조건: UC-01로 만든 계정이 있다.

기본 흐름

1. 방문자가 이메일을 입력하고 로그인용 보안코드를 요청한다.
2. 시스템이 그 이메일로 숫자 8자리 난수를 보낸다.
3. 방문자는 별도 입력 페이지에서 제한 시간 안에 코드를 입력한다.
4. 코드가 맞고 이 코드가 로그인용이며 제한 시간 안이면 인증에 성공한다.
5. 시스템이 httpOnly 쿠키로 세션을 연다.
6. 로그인 사용자의 메모 목록으로 이동한다.

예외 흐름

- 가입된 이메일이 아니면 코드를 보내지 않고 실패를 알린다.
- 코드가 다르거나, 제한 시간이 지났거나, 비밀번호 변경용 코드이면 세션을 만들지 않고 인증 실패를 알린다.

사후 조건: 인증에 성공한 경우에만 해당 계정의 세션 쿠키가 생긴다.

### UC-04 비밀번호 변경

- 액터: 방문자 또는 로그인 사용자
- 사전 조건: UC-01로 만든 계정이 있다. 현재 세션은 없어도 된다.

기본 흐름

1. 사용자가 이메일을 입력하고 비밀번호 변경용 보안코드를 요청한다.
2. 시스템이 그 이메일로 숫자 8자리 난수를 보낸다.
3. 사용자는 별도 입력 페이지에서 제한 시간 안에 코드를 입력한다.
4. 코드가 맞고 이 코드가 비밀번호 변경용이며 제한 시간 안이면 인증에 성공한다.
5. 사용자가 새 비밀번호를 입력한다.
6. 시스템이 새 비밀번호의 해시로 기존 해시를 바꾼다. 이전 비밀번호는 보여 주지 않는다.

예외 흐름

- 가입된 이메일이 아니면 코드를 보내지 않고 실패를 알린다.
- 코드가 다르거나, 제한 시간이 지났거나, 로그인용 코드이면 해시를 바꾸지 않고 인증 실패를 알린다.
- 새 비밀번호가 비어 있으면 해시를 바꾸지 않고 입력 오류를 알린다.

사후 조건: 이후 비밀번호 로그인은 새 비밀번호로만 된다. 이 흐름은 새 세션을 만들지 않는다. 이미 있던 세션 쿠키는 유지된다.

### UC-05 로그아웃

- 액터: 로그인 사용자
- 사전 조건: 세션 쿠키가 있다.

기본 흐름

1. 사용자가 로그아웃을 선택한다.
2. 시스템이 세션 쿠키를 제거한다.
3. 로그인 화면으로 이동한다.

사후 조건: 그 브라우저에서는 메모, 태그, 필터에 접근하지 못한다.

## 메모

### UC-06 메모 목록 보기

- 액터: 로그인 사용자
- 사전 조건: 로그인되어 있다.

기본 흐름

1. 사용자가 메모 목록을 연다.
2. 시스템은 그 계정의 메모를 최근 수정 순으로 보여 준다.
3. 필터가 적용된 경우에는 UC-18 또는 UC-20의 결과만 보여 준다.

사후 조건: 다른 계정의 메모는 목록에 없다.

### UC-07 메모 추가

- 액터: 로그인 사용자
- 사전 조건: 로그인되어 있다.

기본 흐름

1. 사용자가 메모 추가를 선택한다.
2. 시스템이 빈 마크다운 본문의 메모를 그 계정에 만들고 편집 화면을 연다.
3. 저장 상태는 저장됨이다.

사후 조건: 빈 메모가 목록에 나타난다. 이후 본문 변경의 서버 반영은 UC-09 또는 UC-10을 따른다.

### UC-08 메모 편집

- 액터: 로그인 사용자
- 사전 조건: 그 계정의 메모 편집 화면이 열려 있다.

기본 흐름

1. 사용자가 위지윅에서 본문을 수정한다.
2. 화면의 현재 편집본이 바뀌고, 입력은 저장 요청이 끝나기를 기다리지 않는다.
3. 서버의 마지막 저장본과 현재 편집본이 다르면 이 메모는 저장 대기 상태가 된다.
4. 서버 반영은 UC-09 또는 UC-10이 수행한다.

사후 조건: 편집 내용이 화면에 남아 있다. 저장에 성공하기 전에는 다른 기기 목록의 마지막 저장본이 바뀌지 않는다.

### UC-09 수동 저장

- 액터: 로그인 사용자
- 사전 조건: 편집 화면이 열려 있고, 현재 편집본이 이 화면이 기준으로 삼은 마지막 저장본과 다르다.

기본 흐름

1. 사용자가 수동 저장을 선택한다.
2. 저장 상태가 저장 중이 된다. 그 사이에도 위지윅 입력은 계속된다.
3. 시스템이 요청 시점의 본문 스냅샷을 서버로 보낸다.
4. 서버의 마지막 저장 버전이 이 편집 화면의 기준 버전과 같으면 스냅샷을 마지막 저장본으로 기록한다.
5. 응답이 도착했을 때 화면 본문이 그 스냅샷과 같으면 저장 상태는 저장됨이 된다.
6. 응답이 도착했을 때 화면 본문이 더 바뀌어 있으면 저장 대기로 남고, 사용자는 다시 저장할 수 있다.

예외 흐름

- 서버의 마지막 저장 버전이 이 화면의 기준 버전과 다르면 서버 본문을 덮어쓰지 않고 저장 상태를 충돌로 둔다. 해결은 UC-11을 따른다.
- 네트워크 오류나 서버 오류이면 화면 본문은 유지하고 저장 상태를 실패로 둔다. 사용자는 수동 저장으로 다시 시도한다.

사후 조건: 성공한 경우에만 그 스냅샷이 계정의 마지막 저장본이 된다.

### UC-10 주기적 자동 저장

- 액터: 로그인 사용자
- 사전 조건: 편집 화면이 열려 있다. 자동 저장 주기는 앱에 정해 둔 값이며, 길이는 이 문서에서 정하지 않는다.

기본 흐름

1. 주기마다 시스템이 저장 대기 중인 변경이 있는지 확인한다.
2. 변경이 있으면 UC-09의 2단계부터 같은 저장 동작을 수행한다. 사용자가 저장 버튼을 누르지 않아도 된다.
3. 변경이 없거나 이미 저장 중이면 이번 주기에는 새 요청을 보내지 않는다.

예외 흐름

- UC-09와 같다. 충돌이면 자동으로 덮어쓰지 않고 저장 상태를 충돌로 둔다.
- 실패이면 화면 본문을 유지한 채 다음 주기 또는 수동 저장으로 다시 시도할 수 있다.

사후 조건: UC-09와 같다.

### UC-11 동기화 충돌 해결

- 액터: 로그인 사용자
- 사전 조건: 저장 상태가 충돌이다. 서버에는 이 편집 화면의 기준보다 새로운 마지막 저장본이 있다.

기본 흐름

1. 시스템이 충돌 상태를 보여 주고, 마지막 저장본을 살릴지 현재 편집본을 살릴지 선택을 요청한다.
2. 사용자가 마지막 저장본을 고르면 화면 본문을 서버의 마지막 저장본으로 바꾸고, 그 버전을 새 기준으로 삼는다. 저장 상태는 저장됨이 된다.
3. 사용자가 현재 편집본을 고르면 현재 편집본으로 서버의 마지막 저장본을 덮어쓰고, 그 결과를 새 기준으로 삼는다. 저장 상태는 저장됨이 된다.

예외 흐름

- 현재 편집본으로 덮어쓰는 요청이 실패하면 화면의 현재 편집본은 유지하고 저장 상태는 충돌로 남는다.
- 사용자가 선택하기 전에는 자동 저장과 수동 저장 모두 서버 본문을 바꾸지 않는다.

사후 조건: 선택한 쪽이 서버와 화면의 같은 기준 버전이 된다.

### UC-12 메모 삭제

- 액터: 로그인 사용자
- 사전 조건: 그 계정의 메모가 있다.

기본 흐름

1. 사용자가 메모 삭제를 선택한다.
2. 시스템이 그 메모와, 그 메모에 연결된 태그 연결만 제거한다.
3. 메모 목록에서 그 메모가 사라진다.

사후 조건: 태그 자체와 다른 메모의 연결은 남아 있다. 삭제된 메모의 본문은 더 이상 조회되지 않는다.

## 태그

### UC-13 태그 추가

- 액터: 로그인 사용자
- 사전 조건: 로그인되어 있다.

기본 흐름

1. 사용자가 태그 이름을 입력하고 추가한다.
2. 시스템이 그 계정의 태그 목록에 태그를 만든다.

예외 흐름

- 이름이 비어 있으면 만들지 않고 입력 오류를 알린다.
- 같은 계정에 같은 이름의 태그가 있으면 만들지 않고 그 사실을 알린다.

사후 조건: 새 태그가 목록에 있다. 아직 어떤 메모와도 연결되어 있지 않다.

### UC-14 태그 이름 수정

- 액터: 로그인 사용자
- 사전 조건: 그 계정의 태그가 있다.

기본 흐름

1. 사용자가 태그의 새 이름을 입력한다.
2. 시스템이 그 태그의 이름을 바꾼다.
3. 그 태그가 연결된 모든 메모와, 그 태그를 가리키는 저장 필터에 새 이름이 반영된다.

예외 흐름

- 이름이 비어 있거나, 같은 계정에 이미 있는 이름이면 바꾸지 않고 오류를 알린다.

사후 조건: 태그 식별자는 유지되고 이름만 바뀐다. 연결은 끊어지지 않는다.

### UC-15 태그 삭제

- 액터: 로그인 사용자
- 사전 조건: 그 계정의 태그가 있다.

기본 흐름

1. 사용자가 태그 삭제를 선택한다.
2. 시스템이 그 태그와, 그 태그로 이어진 메모 연결을 모두 제거한다.
3. 저장된 필터의 포함 목록과 제외 목록에서도 그 태그를 뺀다.

사후 조건: 메모 본문은 남아 있다. 다른 태그와 그 연결은 남아 있다.

### UC-16 메모에 태그 연결

- 액터: 로그인 사용자
- 사전 조건: 그 계정의 메모와 태그가 있다.

기본 흐름

1. 사용자가 메모에서 계정 태그 목록 중 하나를 골라 연결한다.
2. 시스템이 그 메모와 그 태그의 연결을 만든다.
3. 메모에 그 태그가 표시된다.

예외 흐름

- 이미 연결된 태그이면 연결을 중복으로 만들지 않는다.

사후 조건: 같은 태그를 다른 메모에도 따로 연결할 수 있다. 연결만으로 태그 이름이 복사되지는 않는다.

### UC-17 메모에서 태그 연결 제거

- 액터: 로그인 사용자
- 사전 조건: 메모와 태그 사이에 연결이 있다.

기본 흐름

1. 사용자가 그 메모에서 연결 제거를 선택한다.
2. 시스템이 그 메모와 그 태그 사이의 연결만 제거한다.

사후 조건: 태그는 계정 목록에 남아 있다. 다른 메모와의 연결도 남아 있다.

## 필터

필터 조건은 세 가지다. 세 조건은 동시에 적용한다. 비어 있는 조건은 그 축을 제한하지 않는다.

- 포함 태그: 나열된 태그가 모두 연결된 메모만 남긴다.
- 제외 태그: 나열된 태그 중 하나라도 연결된 메모는 빼다.
- 키워드: 본문 마크다운에 그 문자열이 포함된 메모만 남긴다. 대소문자는 구분하지 않는다. 키워드는 하나다.

예: 포함이 `업무`, `긴급`이고 제외가 `개인`이며 키워드가 `회의`이면, 업무와 긴급이 모두 연결되어 있고 개인은 없으며 본문에 `회의`가 있는 메모만 보인다.

### UC-18 필터 조건으로 메모 보기

- 액터: 로그인 사용자
- 사전 조건: 로그인되어 있다.

기본 흐름

1. 사용자가 포함 태그, 제외 태그, 키워드를 입력한다.
2. 시스템이 위 규칙으로 그 계정의 메모를 걸러 최근 수정 순으로 보여 준다.
3. 이 흐름만으로는 조건을 저장하지 않는다.

예외 흐름

- 포함과 제외에 같은 태그가 있으면 결과를 만들지 않고 조건 오류를 알린다.

사후 조건: 화면의 목록이 조건 결과와 같다. 저장된 필터 목록은 변하지 않는다.

### UC-19 필터 조건 저장

- 액터: 로그인 사용자
- 사전 조건: 포함 태그, 제외 태그, 키워드로 이루어진 조건이 있다.

기본 흐름

1. 사용자가 필터 이름을 입력하고 현재 조건의 저장을 선택한다.
2. 시스템이 그 계정의 필터 목록에 이름, 포함 태그, 제외 태그, 키워드를 저장한다.
3. 태그 조건은 태그 이름이 아니라 태그 식별자를 가리킨다.

예외 흐름

- 이름이 비어 있으면 저장하지 않고 입력 오류를 알린다.
- 포함과 제외에 같은 태그가 있으면 저장하지 않고 조건 오류를 알린다.
- 같은 계정에 같은 이름의 필터가 있으면 저장하지 않고 그 사실을 알린다.

사후 조건: 저장된 필터가 목록에 나타난다. UC-14의 이름 수정과 UC-15의 삭제가 이 필터의 태그 참조에 반영된다.

### UC-20 저장된 필터로 메모 목록 보기

- 액터: 로그인 사용자
- 사전 조건: UC-19로 저장한 필터가 있다.

기본 흐름

1. 사용자가 저장된 필터 목록에서 하나를 선택한다.
2. 시스템이 그 필터의 포함 태그, 제외 태그, 키워드로 UC-18과 같은 규칙의 메모 목록을 보여 준다.

사후 조건: 보이는 메모는 그 계정의 메모이며, 선택한 필터 조건과 같다.
