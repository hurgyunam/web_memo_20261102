- 이메일이 없거나 비밀번호가 다르면 세션을 만들지 않고 로그인 실패를 보여 준다.
- 어떤 화면에도 저장된 비밀번호나 해시를 다시 보여 주지 않는다.
- 로그아웃하면 세션 쿠키가 제거되고 로그인 화면으로 이동한다.
- 로그아웃한 브라우저에서는 메모, 태그, 필터에 접근하지 못한다.

## TODO-04 이메일 보안코드 로그인과 비밀번호 변경

관련: UC-03, UC-04. 선행: TODO-03.

완료 조건

- 가입된 이메일로 로그인을 요청하면 그 이메일로 숫자 8자리 난수를 보내고 별도 입력 페이지로 이동한다.
- 가입된 이메일로 비밀번호 변경을 요청하면 그 이메일로 숫자 8자리 난수를 보내고 별도 입력 페이지로 이동한다.
- 가입되지 않은 이메일이면 코드를 보내지 않고 실패를 보여 준다.
- 앱에 보안코드 제한 시간이 하나 정해져 있다. 그 시간 안에 목적과 같은 코드를 입력하면 인증된다.
- 로그인용 코드 인증에 성공하면 httpOnly 세션 쿠키가 생기고 메모 목록으로 이동한다.
- 비밀번호 변경용 코드 인증에 성공한 뒤에만 새 비밀번호를 입력받는다.
- 새 비밀번호를 저장하면 기존 해시가 새 해시로 바뀌고, 이전 비밀번호는 보여 주지 않는다.
- 비밀번호 변경은 새 세션을 만들지 않는다. 이미 있던 세션 쿠키는 유지된다.
- 변경 이후의 비밀번호 로그인은 새 비밀번호로만 성공한다.
- 코드가 다르거나, 제한 시간이 지났거나, 다른 목적의 코드이면 세션을 만들거나 해시를 바꾸지 않고 인증 실패를 보여 준다.
- 새 비밀번호가 비어 있으면 해시를 바꾸지 않고 입력 오류를 보여 준다.

## TODO-05 메모 목록, 추가, 삭제

관련: UC-06, UC-07, UC-12. 선행: TODO-03. 필터가 적용된 목록은 TODO-11에서 확인한다. 태그가 연결된 메모의 삭제는 TODO-10에서 다시 확인한다.

완료 조건

- 로그인한 사용자의 메모만 최근 수정 순으로 목록에 나온다.
- 다른 계정의 메모는 목록과 조회 결과에 없다.
- 메모 추가를 선택하면 빈 마크다운 메모가 그 계정에 생기고 편집 화면이 열린다.
- 추가 직후 저장 상태는 저장됨이고, 그 빈 메모가 목록에 나타난다.
- 메모를 삭제하면 그 메모가 제거되고 목록에서 사라지며, 본문은 다시 조회되지 않는다.
- 메모 삭제는 그 메모의 태그 연결만 지우도록 구현되어 있고, 태그 행은 지우지 않는다.

## TODO-07 수동 저장과 자동 저장

관련: UC-09, UC-10. 선행: TODO-06. 충돌 선택은 TODO-08이 담당한다.

완료 조건

- 화면에 저장 중, 저장됨, 실패, 충돌이 서로 구분되어 표시된다.
- 저장 대기가 있을 때 수동 저장을 선택하면 그 시점의 본문 스냅샷을 서버로 보내고, 그동안 상태는 저장 중이다.
- 저장 중에도 위지윅 입력은 계속된다.
- 서버의 저장 버전이 이 화면의 기준 버전과 같고, 응답 시점의 화면 본문이 스냅샷과 같으면 그 스냅샷이 마지막 저장본이 되고 상태는 저장됨이다.
- 응답 시점의 화면 본문이 스냅샷과 다르면 저장 대기로 남고, 다시 저장할 수 있다.
- 서버의 저장 버전이 이 화면의 기준 버전과 다르면 서버 본문을 덮어쓰지 않고 상태를 충돌로 둔다.
- 네트워크 오류나 서버 오류이면 화면 본문은 유지되고 상태는 실패이며, 수동 저장으로 다시 시도할 수 있다.
- 앱에 자동 저장 주기가 하나 정해져 있다. 주기가 되었을 때 저장 대기가 있고 저장 중이 아니면, 수동 저장과 같은 저장 동작을 사용자 조작 없이 수행한다.
- 저장 대기가 없거나 이미 저장 중이면 그 주기에는 요청을 보내지 않는다.
- 자동 저장이 충돌이거나 실패이면 화면 본문을 유지하고, 서버 본문을 자동으로 덮어쓰지 않는다.

## TODO-08 동기화 충돌 해결

관련: UC-11. 선행: TODO-07.

완료 조건

- 충돌 상태에서 마지막 저장본을 살릴지, 현재 편집본을 살릴지 선택할 수 있다.
- 선택 전에는 수동 저장과 자동 저장이 서버 본문을 바꾸지 않는다.
- 마지막 저장본을 고르면 화면 본문이 서버의 마지막 저장본으로 바뀌고, 그 버전이 새 기준이 되며 상태는 저장됨이다.
- 현재 편집본을 고르면 현재 편집본이 서버의 마지막 저장본을 덮어쓰고, 그 결과가 새 기준이 되며 상태는 저장됨이다.
- 현재 편집본으로 덮어쓰는 요청이 실패하면 화면의 현재 편집본은 유지되고 상태는 충돌로 남는다.

## TODO-09 태그 목록

관련: UC-13, UC-14, UC-15. 선행: TODO-03. 연결된 메모의 표시는 TODO-10에서, 저장 필터 반영은 TODO-11에서 확인한다.

완료 조건

- 로그인한 계정의 태그만 목록에 나온다.
- 이름을 입력하면 그 계정에 태그가 생기고, 생성된 직후에는 어떤 메모와도 연결되어 있지 않다.
- 이름이 비어 있으면 만들지 않고 입력 오류를 보여 준다.
- 같은 계정에 같은 이름이 있으면 만들지 않고 그 사실을 보여 준다.
- 이름을 수정하면 태그 식별자는 유지되고 이름만 바뀐다. 이미 있는 메모 연결은 끊어지지 않는다.
- 새 이름이 비어 있거나 같은 계정에 이미 있으면 바꾸지 않고 오류를 보여 준다.
- 태그를 삭제하면 그 태그와, 그 태그로 이어진 모든 메모 연결이 제거된다.
- 태그를 삭제한 뒤에도 메모 본문과 다른 태그의 연결은 남아 있다.
- 다른 계정의 태그는 조회, 수정, 삭제되지 않는다.

## TODO-10 메모와 태그 연결

관련: UC-16, UC-17. UC-12의 연결 정리와 UC-14의 표시 이름 반영을 여기서 확인한다. 선행: TODO-05, TODO-09.

완료 조건

- 메모 화면에서 그 계정의 태그 중 하나를 고르면 연결과 메모의 태그 표시가 생긴다.
- 이미 연결된 태그를 다시 골라도 연결은 하나다.

- 연결은 태그 이름을 메모에 복사하지 않는다. 태그 이름을 바꾸면 연결된 메모의 표시 이름이 함께 바뀐다.
- 메모에서 연결을 제거하면 그 메모와 그 태그 사이의 연결만 사라진다. 태그와 다른 메모의 연결은 남는다.
- 메모를 삭제하면 그 메모의 태그 연결만 사라진다. 태그 자체와 다른 메모의 연결은 남는다.
- 다른 계정의 태그로는 연결하지 못한다.

## TODO-11 필터

관련: UC-18, UC-19, UC-20. UC-06의 필터 목록, UC-14와 UC-15의 필터 반영을 여기서 확인한다. 선행: TODO-10.

완료 조건

- 포함 태그, 제외 태그, 키워드를 입력하면 그 계정의 메모를 걸러 최근 수정 순으로 보여 준다. 이 조회만으로 저장 필터 목록은 변하지 않는다.

- 포함이 `업무`와 `긴급`, 제외가 `개인`, 키워드가 `회의`이면, 업무와 긴급이 모두 연결되어 있고 개인은 없으며 본문에 `회의`가 있는 메모만 보인다.
- 포함과 제외에 같은 태그가 있으면 목록을 만들지 않고 조건 오류를 보여 준다.
- 필터 이름을 입력하고 저장하면 그 계정의 필터 목록에 이름, 포함 태그 식별자, 제외 태그 식별자, 키워드가 저장된다.
- 이름이 비어 있으면 저장하지 않고 입력 오류를 보여 준다.
- 포함과 제외에 같은 태그가 있으면 저장하지 않고 조건 오류를 보여 준다.
- 같은 계정에 같은 이름의 필터가 있으면 저장하지 않고 그 사실을 보여 준다.
- 저장된 필터를 선택하면 그 조건과 같은 규칙의 메모 목록이 보인다. 다른 계정의 메모는 보이지 않는다.
- 태그 이름을 수정하면 그 태그를 가리키는 저장 필터의 표시 이름이 바뀌고, 필터는 같은 태그를 계속 가리킨다.
- 태그를 삭제하면 저장 필터의 포함 목록과 제외 목록에서 그 태그만 빠진다.
